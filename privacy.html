Privacy Policy

Hermes Agent  ·  Last updated: November 5, 2026

Hermes Agent ("the application") is a private, single-user automation tool operated by one individual ("the operator") for their own Google Account. This policy explains what Google user data the application accesses, how it is used, stored, and shared.

1. Who operates this application

The application is operated by a single individual as a personal automation project. It is not a commercial service, has no other users, and is not offered to the public. There is no sign-up and no account creation. The only Google Account it can access is the operator's own.

2. What Google user data is accessed

  • Gmail (read-only, gmail.readonly). The application reads messages in the operator's own mailbox in order to identify school communications and extract scheduling details such as minimum days and early dismissals. It cannot read mail from any other account, and it cannot modify, delete, or send mail.
  • Google Calendar (calendar). The application may read the operator's own calendars to cross-check dates and scheduling.

No other Google data is accessed. Specifically, the application does not access Google Drive, Contacts, Photos, or any data belonging to anyone other than the operator.

3. How the data is used

Gmail and Calendar data is used solely to produce reminders for the operator — for example, notifying the operator that an upcoming school day ends early. This is the only purpose. The data is not used for advertising, marketing, profiling, creditworthiness, or lending decisions, and it is not used to train or improve machine-learning models.

4. How the data is stored

All retrieved data stays on the operator's own computer, on local storage controlled by the operator. The application runs locally on that machine. No Google user data is uploaded to, stored on, or processed by any third-party server, cloud service, or database operated by anyone else.

OAuth credentials are stored locally on the operator's machine in a file readable only by the operator's user account.

5. How the data is shared

Google user data is not shared, sold, rented, or transferred to any third party, and is not disclosed to any other person. Summaries derived from the data (for example, the text of a reminder) are delivered only to the operator, through the operator's own messaging account.

6. Retention and deletion

  • Cached message contents are kept locally and are pruned periodically; they never leave the operator's machine.
  • The operator can delete all locally stored data at any time by removing the application's local data directory.
  • Access can be revoked at any time, which immediately stops all data access, at myaccount.google.com/permissions.

7. Compliance with Google's Limited Use requirements

The application's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. In particular, the application:

  • limits its use of Google user data to providing and improving the single feature described above;
  • does not transfer Google user data to third parties except as necessary to provide that feature, as required by law, or with the operator's explicit consent;
  • does not use Google user data for advertising, including retargeting, personalized, or interest-based advertising;
  • does not allow humans to read Google user data, except the operator reading their own data; and
  • does not use Google user data to determine creditworthiness or for lending purposes.

8. Children's privacy

The application is not directed to children and is not used by anyone other than the operator.

9. Security

Access is granted through Google OAuth 2.0 with scopes limited to the minimum needed. Credentials are stored locally on the operator's own machine. Access can be revoked by the operator at any time as described in section 6.

10. Changes to this policy

If this policy changes, the "Last updated" date above will be revised.
